# Terraform Plugin Code Generation for Cisco NDFC

This project uses two code generators:

1. **`generator`** (tfgenerator) -- custom tool that reads YAML definitions and produces Go schema, codec, compare, and test code
2. **`tfplugingen-framework`** -- HashiCorp's official Terraform Framework Code Generator (used internally by the pipeline)

## Prerequisites

All four tools must be installed in `$GOPATH/bin`:

### 1. Terraform Framework Code Generator (`tfplugingen-framework`)

https://developer.hashicorp.com/terraform/plugin/code-generation/framework-generator

```
go install github.com/hashicorp/terraform-plugin-codegen-framework/cmd/tfplugingen-framework@latest
```

### 2. Custom Generator (`generator`)

**Note:** The generator code is private. Contact muralidm@cisco.com for access.

```
Repo: https://github.com/ciscoecosystem/nd-codegen
Clone the repo and run `go install .`
Binary: $GOPATH/bin/generator
Branch: nd4_nestings

```

**Important:** Before running generation, ensure the generator repo is on the correct branch and up to date. Always rebuild after `git pull`:

```
cd <path-to-tfgenerator>
git checkout nd4_nestings
git pull
go install .
```

### 3. License Header Tool (`addlicense`)

Uses a customized fork -- do NOT use the upstream version.

```
Repo: https://github.com/mdmohan/addlicense
Clone the repo and run `go install .`
Binary: $GOPATH/bin/addlicense
```

### 4. Terraform Plugin Docs (`tfplugindocs`)

https://github.com/hashicorp/terraform-plugin-docs

```
go install github.com/hashicorp/terraform-plugin-docs/cmd/tfplugindocs@latest
```

## How to Run

From the repo root:

```bash
go generate
```

This runs the full pipeline: YAML -> Go code -> license headers -> examples -> docs.

For detailed working of the `tfgenerator` tool, check the documentation in https://github.com/ciscoecosystem/nd-codegen

## Adding a New Resource

1. **Create the YAML definition** in `generator/defs/` (e.g. `interface_loopback.yaml`)
   - Set `category` (`manage` or `infra`) -- determines the output subdirectory
   - Set `doc_category` (e.g. `Interface Management`) -- must be listed in `doc_categories.yaml`; add it there if new
   - If using a shared model, set `parent_package` and `parent_model` (see [Inherited model pattern](#inherited-model-pattern))
   - Define all attributes with proper types, descriptions, examples, and flags
   - See [fields.md](fields.md) for detailed help on attribute fields

2. **Register in `defs.yaml`** -- add the filename to the `files:` list. Only files in this list are processed.

3. **Run generation:**
   ```bash
   go generate ./...
   ```

4. **Verify:**
   - Check generated files in `internal/{category}/resource_<name>/` (see [Generated output](#generated-output))
   - Check `examples/resources/nd_<name>/resource.tf`
   - Check `docs/resources/<name>.md`
   - Run `go build ./...` to verify compilation

5. **Write implementation files** in `internal/{category}/resource_<name>/`:
   - `init.go` -- register with the resource registry
   - `<name>.go` -- CRUD operations (typically delegating to common functions)
   - `resource_custom_codec.go` -- custom marshaling if needed
   - `validators.go` -- validation logic

6. **NEVER edit `_gen.go` files.** If generated code is incorrect, fix the YAML definition and regenerate.

Report any generator errors to muralidm@cisco.com

## Generated Output

On successful generation, the following files are produced:

### Per resource (`internal/{category}/resource_<name>/`)

| File | Description |
|---|---|
| `<name>_resource_gen.go` | TF Schema definitions and model types (from `tfplugingen-framework`) |
| `resource_codec_gen.go` | Marshal/unmarshal between TF model and Go/JSON structs |
| `resource_compare_gen.go` | DeepEqual-style comparison for bulk/map resources (e.g. resources carrying multiple objects). Not generated for simple resources. |
| `resource_<name>_test.go` | Helper functions for acceptance tests (`ModelHelperStateCheck`) |

### Provider registration (`internal/provider/`)

| File | Description |
|---|---|
| `register_resource_<name>_gen.go` | Blank import that auto-registers the resource with the provider. No manual import needed. |

### Documentation and examples

| File | Description |
|---|---|
| `examples/resources/nd_<name>/resource.tf` | HCL example constructed from `example:` fields in the YAML attributes |
| `docs/resources/<name>.md` | Terraform registry documentation (generated by `tfplugindocs`) |

The `doc_category` YAML field determines the sidebar subcategory in the generated docs. Allowed values are listed in `generator/defs/doc_categories.yaml`.

## Input Structure

```
generator/
  defs/
    defs.yaml                  # Manifest -- lists all YAML files to process
    doc_categories.yaml        # Allowed doc subcategories for generated docs
    <resource>.yaml            # Resource/datasource definitions
  templates/                   # Go templates used by the generator for codec/compare/test
  doc_category.go              # Post-processor that patches subcategory into generated docs
```

## YAML Definition Reference

### Resource-level fields

| Field | Description |
|---|---|
| `name` | Resource name (used in package and file names) |
| `generate_tf_resource` | `true` to generate a TF resource; `false` for model-only (e.g. `interface_common`) |
| `inherited_model` | `true` if this YAML defines a shared model used by child resources |
| `category` | Output category: `manage` or `infra`. Determines the output subdirectory under `internal/`. |
| `doc_category` | Documentation subcategory (e.g. `Interface Management`). Must be listed in `doc_categories.yaml`. |
| `parent_package` | For child resources: package containing the shared model (e.g. `resource_interface_common`) |
| `parent_model` | For child resources: name of the parent YAML definition (e.g. `interface_common`) |
| `skip_equality` | Skip generating compare functions |
| `import_id` | Array of sample import IDs for documentation |
| `import_desc` | Array of descriptions for each import ID format |

### Inherited model pattern

For resources that share a common data model (e.g. all interface types share `interface_common`):

1. Define the shared model in a YAML with `generate_tf_resource: false` and `inherited_model: true` (e.g. `interface_common.yaml`)
2. Child resources reference it via `parent_package` and `parent_model` (e.g. `interface_ethernet.yaml`)
3. The child's TF schema is generated independently but its codec uses the parent's Go struct
4. Both YAMLs must be listed in `defs.yaml`

### Attribute-level fields

See [fields.md](fields.md) for the full attribute field reference including type mappings, computed/optional/mandatory behavior, validation, payload control, and special flags.

## Files to Commit

After generation, commit:
- `generator/defs/<name>.yaml` and changes to `generator/defs/defs.yaml`
- `internal/{category}/resource_<name>/*_gen.go`
- `internal/provider/register_resource_<name>_gen.go`
- `internal/provider/{category}/resource_<name>/*` (generated staging copies and test helpers)
- `examples/resources/nd_<name>/resource.tf`
- `docs/resources/<name>.md`
- Any changes to `doc_categories.yaml` if a new category was added
